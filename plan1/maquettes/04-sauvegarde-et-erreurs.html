4. Sauvegarde automatique, toasts et flux

Le dessin est sauvegarde pendant le geste (debounce 400 ms, comme l'auto-save des fiches) et signale par le toast de sauvegarde existant (showToastSave(), disquette 💾, anti-rebond 600 ms). Aucune action « Enregistrer » n'existe dans le module.

Import — image absente (R11) — un toast par UID introuvable ; la grille par defaut est conservee, le dessin est lui importe.

Erreur de sauvegarde

Echec reseau / session expiree — le dessin reste en memoire, un nouvel evenement de dessin relance la sauvegarde.

Flux — image de fond
1. Choix« Charger une image de fond » → selecteur de fichiers (image/webp,image/*)
→
2. UploadPOST api/map-image.php → UID genere (bin2hex(random_bytes(16))) + conversion webp (GD, qualite 85)
→
3. Stockagedata/maps/[UID].webp — jamais de binaire en base, jamais dans le JSON
→
4. Affichage<img src="api/map-image.php?uid=[UID]"> (session obligatoire, Cache-Control: private)
→
5. Sauvegardemaps.save(bg_uid, bg_name) + 💾 — le nom utilisateur = nom de fichier d'origine, editable
Flux — suppression d'une carte (R12)
1. Confirmation« Supprimer cette carte » → confirmation en 2 temps (rappel du fichier data/maps/[UID].webp)
→
2. APImaps.php?action=delete → suppression de la ligne maps
→
3. Imagesi plus aucune carte ne cite cet UID → unlink data/maps/[UID].webp (D9 : comptage des references)
→
4. Retourcalque suivant charge, toast « Carte supprimee »

2. Confirmation« remplace tous vos personnages et vos cartes » (action irreversible)

→
4. Rapport{maps, images, missing[]} → toast succes + un toast d'erreur par UID manquant (R11)

Questions ouvertes — arbitrees le 07/10/2026
ALimite de 10 cartes par compte (D12) : creation refusee des la 11ᵉ avec le message « Limite de 10 cartes atteinte — supprimez-en une pour en creer une nouvelle ». Un import « tout » au dela importe les 10 premiers et liste les calques ecartes dans un toast d'erreur (D13).
BConcurrence multi-onglets : dernier ecrit gagne, sans risque de corruption (D14) — SQLite (mode WAL) ecrit par transactions atomiques : la base reste coherente meme en cas de crash. Seul risque reel : une perte d'ecriture si deux onglets modifient la meme carte (le sauvegarde le tableau d'operations complet) ; deux cartes distinctes ne se genent pas. Mesures : busyTimeout(5000) cote serveur + comportement documente dans MANUAL.md.
CPartage d'une image entre deux cartes : interdit (D9) — chaque image appartient a un seul calque, ce qui simplifie la suppression effective du fichier (R12).
DPNG / JPG / JPEG : convertis en webp a l'import (D4) — conversion serveur (GD, qualite 85), les metadonnees EXIF (dont le GPS des photos) sont effacees ; replis : conversion cote navigateur (canvas.toBlob('image/webp')) puis, en dernier recours, refus avec message explicite. Un webp est conserve tel quel.
